# 逃离西撇镇 UX 设计交付（确认稿）

## 1. 设计目标

“逃离西撇镇”作为 NBYS 活动系统中的独立玩法模块，不改变现有活动报名、签到、租赁和用户资料的主流程。H5 延续现有深色移动优先风格，后台延续 Element Plus 的浅色运营工作台。

设计原则：

1. 资产可信：现金、仓库容量、物品状态和每次变更原因可追溯。
2. 状态明确：整备、锁定、进行、待结算、已结束均有独立状态，不只依赖颜色。
3. 隐私优先：开局前普通用户只能看到其他参与者呼号；开局后只展示本队配装。管理员可查看全量。
4. 低耦合：玩法模块拥有独立导航、权限、接口域和数据表；只复用统一用户、场地、认证、文件上传能力。
5. 防误操作：锁定配装、开始战局、最终结算、硬删除物品、调整资产必须二次确认。

## 2. 信息架构

### H5 玩家端

- 模块入口：现有首页运营横幅（管理员上传原图，建议 1120×310）

## 3. 关键流程

### 玩家参战

模块入口 → 战局详情 → 选择小队 → 选择职业 → 选择武器 → 查看费用/风险 → 保存 → 锁定 → 等待管理员开局。

锁定前允许修改；锁定后不可修改。若使用特殊武器，锁定时只冻结资产，不扣耐久。战局开始后进入使用中；成功撤离时耐久减一并返还，失败时销毁。

### 管理员开局

创建战局 → 设置场地/小队数量/上限 → 玩家加入并锁定 → 系统校验全员锁定及余额/资产 → 管理员二次确认 → 扣除职业维护费和普通武器费 → 冻结特殊武器 → 状态变为进行中。

任何校验失败时必须列出具体用户和原因，不允许部分开局。

### 最终结算

逐个用户录入撤离、击杀、手工现金和物品 → 系统自动计算击杀现金 → 预览全部变更 → 管理员二次确认 → 单事务结算 → 生成不可变结算单与资产流水。

最终结算必须支持幂等请求，禁止重复发钱或重复入库。

## 4. 页面状态

每个列表与详情页都必须覆盖：

- 初次加载骨架
- 空数据
- 网络失败与重试
- 无权限
- 数据已被他人修改（版本冲突）
- 已停用/已结束
- 提交中与防重复提交

仓库额外覆盖：格位不足、物品尺寸不匹配、暂存仓库即将自动出售、拖拽失败、并发移动冲突。

战局额外覆盖：余额不足、武器不存在、特殊武器已被占用、队伍已满、有人未锁定、结算已完成。

## 5. 视觉规范

### H5

- 背景：`#070B0D`
- 一级面板：`#11181B`
- 强调色：`#A5D52E`（军绿/酸性绿，仅用于主操作与选中态）
- 警告：`#E0A63B`
- 危险：`#E45C5C`
- 物品稀有度：超凡红、史诗橙、精品紫、普通蓝
- 圆角：8 / 10 / 14 px
- 触控目标：最小 44×44 px
- 正文：最小 12 px；辅助信息最小 10 px

### 后台

- 延续现有 `#111827` 侧栏、`#2563EB` 主操作和浅灰工作区
- 表格高风险操作使用文字按钮并要求二次确认
- 资产变更必须展示变更前、变更后、原因和操作者
- 1280 px 为主要设计宽度，1100 px 以下允许主内容横向滚动；后台不作为手机端核心场景

## 6. 权限建议

独立权限前缀建议为 `escape:*`：

- `escape:view`
- `escape:match:view/create/update/start/settle`
- `escape:item:view/create/update/delete`
- `escape:shop:view/create/update/delete`
- `escape:season:view/create/update/enable`
- `escape:class:view/create/update/delete`
- `escape:weapon:view/create/update/delete`
- `escape:userAsset:view/adjust`
- `escape:itemGrant:create`
- `escape:audit:view`

逃离管理员默认获得以上业务权限，普通管理员不应因现有 `activity:*` 自动获得资产调整和结算权限。

## 7. 开发边界

- H5 前端：在 `h5-web` 内新增独立模块组件与路由状态，不继续扩大 `MemberApp.vue` 单文件。
- 后台前端：在 `admin-web` 内新增独立页面组件和 API 文件，不继续把全部界面加入 `App.vue`。
- 后端：建议新增 `escape-center` 微服务；若首期仍放入 `activity-center`，必须以独立 package、service、repository、controller 和数据库迁移隔离。
- 复用：统一认证、用户 ID、场地、文件上传、API 网关、权限模型。
- 不复用：现有活动报名表、签到状态、发射器租赁、活动小队数据。
- 数据库只通过迁移脚本变更；先在 SSH 隧道连接的预发布/备份库验证，禁止手工改生产表。

## 8. 待产品确认

1. 普通用户是否能创建战局，还是仅“逃离管理员”可创建？
2. 暂存仓库每日 05:00 自动出售时，价格按 05:00 刷新前还是刷新后的当日价格？
3. 特殊武器成功撤离后耐久减到 0，是立即销毁还是允许本场后展示“损坏”记录再销毁？
4. 物品硬删除会影响历史结算可读性，建议改为停用；是否同意？
5. 管理员手工现金允许负数扣款吗？若允许，余额是否可为负？
6. “扫描物品二维码”首期是本期交付还是只预留入口？

## 9. 原型操作

打开 `index.html`：

- 顶部切换 H5 / 后台
- H5 底部切换战局、仓库、商店、战绩
- 战局主按钮打开配装锁定弹窗
- 仓库点击物品可切换详情
- 后台侧栏切换运营概览、物品、赛季、职业武器、用户资产

本原型只用于 UX 确认，不包含真实接口和生产业务代码。
